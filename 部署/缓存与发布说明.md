# 缓存与发布说明

> 站点是**纯静态**（HTML + 原生 JS），无构建工具。浏览器会对 JS / HTML 做启发式缓存，改代码后若不处理缓存，用户可能一直看到旧版本。

## 现状

- 已为「主站」建立**版本参数链路**：`index.html → main.js?v=NN → tools.js/content.js?v=NN → config.js?v=NN`。
- 只要入口 `main.js?v=NN` 的 `NN` 变化，浏览器就会重新拉取主入口，进而拉取整条 import 链，自动拿到新代码。

## 发版步骤（推荐，最简单可靠）

1. 改完代码后运行：
   ```
   powershell -ExecutionPolicy Bypass -File scripts\bump-version.ps1 -Version 20261005-08
   ```
   （版本号按 `yyyymmdd-NN` 递增，与当前日期保持一致。）
2. 把发布根（`index.html`、`css/`、`js/`、`assets/`、`data/`、导播台三页面）上传到 `ivscl-ivsl.cn`。
3. 若本轮有后端改动，**进入 `D:\ivscl\backend`** 后跑对应迁移 + `npx wrangler deploy --env production`。

## 进阶：托管层控制缓存（可选）

若希望**不依赖版本号**也能保证更新，可在 Cloudflare Pages 上做其中之一：

- **Pages 设置**：把 `/js/*`、`/css/*`、`/index.html` 的 Cache-Control 设为 `no-cache`（每次都回源校验，改动后自动生效）。
- **Pages Functions**：新建 `functions/_middleware.js` 给静态资源加 `Cache-Control: no-cache` 响应头。
- 若接入 CDN/反代，同理对 `index.html` 与 `js/css` 关闭强缓存。

## 备份提醒

- 部署后端或执行迁移前，先跑 `scripts\backup-d1.ps1` 备份 D1 数据。
